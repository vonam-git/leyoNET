    OSPF

    Link-state routing: neighbours via hello, a database of all links, shortest paths by Dijkstra – for IPv4 (OSPFv2) and IPv6 (OSPFv3).

    Layer
    3 (IP-Protokoll 89)
    Standard
    RFC 2328, RFC 5340

    The idea

    With OSPF (Open Shortest Path First) every router knows the whole map of its area: which routers exist and which links with which costs. From this each computes the shortest paths itself with the Dijkstra algorithm. If a line fails, the change spreads immediately and everyone recomputes.

    Sequence

    1. Hello: routers regularly send hello packets to 224.0.0.5. Whoever answers and has the same values (area, network, intervals) becomes a neighbour.
    2. Database exchange: neighbours exchange descriptions (DBD), request missing entries (LSR) and send them (LSU), acknowledged with LSAck.
    3. SPF calculation: every router computes its routes from the database; they appear with “O” in the table.

    The router ID is the highest loopback address, otherwise the highest interface address. The cost of an interface can be set; the path with the smallest sum wins.

    Setting up

    Router(config)# router ospf
Router(config-router)# network 10.0.0.0/24 area 0
Router(config-router)# network 192.168.1.0/24 area 0
Router# show ip ospf neighbor
Router# show ip route

    OSPFv3 does the same for IPv6: neighbours via link-local addresses, configuration per interface instead of with network.

    OSPF or RIP?

    OSPF converges faster, computes with costs instead of hops and scales better. RIP and RIPng is easier to understand and sufficient for small networks.

    OSPF

    OSPF is a link-state protocol: each router describes its links (LSA), all collect the map and compute shortest paths with Dijkstra.

    • Hello finds neighbours (standard every 10 s, shortened to 2 s in the simulator) (multicast 224.0.0.5)
    • DBD, LSR, LSU, LSAck synchronise the database until the neighbour is Full
    • Cost per interface (default 10), adjustable with ip ospf cost

    CLI: router ospf, network 10.0.0.0/24 area 0 (or with wildcard 0.0.0.255), show ip ospf neighbor.

    OSPFv3 (IPv6)

    OSPFv3 (RFC 5340) is OSPF for IPv6. The process is the same as for OSPF: hello, DBD, LSR, LSU, LSAck, then full and Dijkstra. Differences:

    • Routers talk over their link-local addresses; hellos go to ff02::5, IPv6 next header 89.
    • You add interfaces, not networks (in FRRouting ipv6 ospf6 area 0 on the interface).
    • The router ID stays a 32-bit number written like an IPv4 address. If a router has no IPv4 address you should set it (otherwise the simulator derives one from the MAC).
    • Router LSAs only describe the links; the networks are carried in intra-area prefix LSAs.
    • The next hop in the routing table is the neighbour’s link-local address.

    CLI: router ospf6, ospf6 router-id 1.1.1.1, interface eth0 area 0, show ipv6 ospf6 neighbor, show ipv6 ospf6 database, show ipv6 route (code O). Layer 3 switches speak OSPFv3 on their VLAN interfaces.

    Simplified like OSPFv2: no DR/BDR election, no network and link LSAs, one area.

    OSPFv23Router LSAs and external LSAs (redistribution), no summary LSAs between areas, no DR/BDR (neighbours like point-to-point); hello 2 s instead of 10 s; a stuck database exchange (lost DBD/LSR/LSU) is repeated after two hello intervals; hellos from a foreign subnet form no adjacency
