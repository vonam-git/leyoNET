    Understanding the simulation and the packet list

    What happens in the simulation, how to find packets, unpack them layer by layer and save them as a capture for Wireshark.

    See an example

    What the simulation does

    In the simulation every device runs its own process: end devices send ARP, DHCP or pings, switches learn MAC addresses, routers decide by their routing table. Every transmission over a cable is an event with a timestamp. The same sequence therefore always produces the same packets, which makes demonstrations and exercises repeatable.

    Time in the simulation runs like real time; in design mode it stops, and states such as ARP tables are kept. At the top are the buttons Pause, Single step, Step back, Reset and the speed (real time or slow motion).

    The packet list

    At the bottom the packet list shows every frame with time, path (from → to, with interface), protocol and short info. Clicking a row shows the details:

    • OSI view: layers 7 to 1, every field with value and meaning. What leyoNET simplifies is noted at the layer.
    • Structure per standard and nesting: every header drawn as in the RFC or IEEE standard, with the values of this frame (see Structure of frames and packets).
    • Hex view: the real bytes; clicking a field highlights its bytes.
    • Filters like in Wireshark: arp, icmp and ip.dst == 192.168.1.11, tcp.port == 80, not stp. The buttons below set common filters.
    • Export as pcapng: the file opens in Wireshark like a real capture.

    Single step with OSI colours

    In single step mode (key N) every frame travels across the cable as a coloured dot. A switch unpacks it up to layer 2, a router up to layer 3, the destination completely. This makes visible what encapsulation means.

    Proven in class: present a demo, pause with the space bar and continue step by step with N. The class predicts what happens next each time.

    How to do it in leyoNET

    The same text as in the app’s help (F1 key).

    Running the simulation

    • Space pauses or resumes, N takes one step. In single step the canvas has an orange frame and a notice at the top; in single step, arriving packets are unpacked layer by layer (Single step with OSI layers)
    • Choose the speed at the top
    • Double-click an end device: desktop with command prompt, browser and mail. Several desktops can be open; minimise with — and bring them back via «Open desktops» in the simulation bar. Drag a desktop by its title bar and resize it at the bottom right
    • Hover over a device, cable or packet: details (addresses, tables, protocol)
    • Packets visibly travel along the cables; the Packet list shows each one
    • The lights on the cables: green connected, orange data in transit, red no connection
    • Ports and cables can be shut down or damaged at any time to practise troubleshooting Shift+N steps back, «Reset» restarts at time 0.

    Packet list

    The packet list shows every frame crossing a cable: time, path, protocol, source, destination and a summary. Clicking opens the details following the OSI model model. Use the Display filter to hide what you don't need, and pcap export to take the capture into Wireshark. Each packet once hides unchanged forwards by switches; turn it off to see every segment.

    Single step with OSI layers

    When paused, each packet shows its layers nested inside each other, each in its colour (shown at the bottom). Single step (N) unpacks an arriving packet at the receiver layer by layer, and the colour changes:

    • Switch, access point, modem up to layer 2: they read the destination MAC and forward
    • Router up to layer 3: read the destination IP, look up the route, forward (fully unpacked if the packet is for the router itself)
    • End device: fully if the packet is for it; with another destination MAC it is dropped at layer 2

    Only after the last layer does the device process the packet. Resume (Space) continues normally.

    Display filter

    The filter works much like Wireshark's:

    • protocols: arp, dhcp, dns, http, icmp, tcp, udp, stp, ospf, rip, bgp, ppp, wlan, broadcast, IPv6: ipv6, icmpv6, ndp, dhcpv6, dslite, VPN: esp, ike, vpn, data centre: vxlan, lacp
    • comparisons: ip.addr == 10.0.0.1, ip.src, ip.dst, ipv6.addr, ipv6.src, ipv6.dst, eth.addr, port == 80, tcp.port, udp.port, vlan == 10, tcp.stream == 0 (one TCP connection), tcp.flags.syn == 1 (also ack, fin, rst), also with !=
    • host PC1 (device name), lost (lost frames)
    • combine with and, or, not and parentheses
    • Follow TCP stream: click a packet, then “Follow TCP stream”. The list shows only that connection (like “Follow TCP Stream” in Wireshark); the bar on top shows whether setup (SYN, SYN/ACK, ACK), data and teardown (FIN) occurred.

    Example: dhcp or (icmp and host PC1). The chips below the filter set common expressions.

    pcap export

    File → Export capture saves all frames as a pcapng file. Wireshark opens it like a real capture; each link appears as its own interface with the right link type (Ethernet, PPP, Wi-Fi …).
