    VLANs and trunks

    One switch, several separate networks: access ports, trunks with 802.1Q tag, native VLAN and routing between VLANs.

    What for

    Without VLANs a switch is a single network: every broadcast reaches everyone, every device sees every other. A VLAN (virtual LAN) divides the switch into separate networks, e.g. administration, training and guests. Nothing passes between the VLANs without a router; this separates departments and enforces rules.

    Access port and trunk

    Port typeforFrames
    Accessend device, belongs to exactly one VLANwithout tag
    Trunklink between switches or to the router, carries several VLANswith 802.1Q tag (VLAN number)

    The 802.1Q tag is 4 bytes after the MAC addresses: EtherType 0x8100, priority and the 12-bit VLAN ID (1 to 4094). The native VLAN travels on the trunk without a tag; both ends must have the same native VLAN. With “allowed VLANs” a trunk only lets certain VLANs through.

    A switch only forwards VLANs it knows. Even a switch that only passes a VLAN on over trunks needs it in its VLAN database.

    The 802.1Q tag

    On the trunk the switch inserts 4 bytes after the source MAC: TPID 0x8100 and the VLAN number in it. At the access port it removes the tag again. Because the frame changes, the switch recomputes the FCS.

    Routing between VLANs

    • Router on a stick: a router is connected to the switch with a trunk and has one subinterface per VLAN (eth0.10) that serves as the gateway.
    • Layer 3 switch: the switch routes itself via VLAN interfaces (SVIs), see Layer 3 switch.

    Command line

    Switch(config)# vlan 10
Switch(config-vlan)# name ADMIN
Switch(config)# interface range port1-4
Switch(config-if)# switchport access vlan 10
Switch(config)# interface port24
Switch(config-if)# switchport mode trunk
Switch(config-if)# switchport trunk allowed vlan 10,20
Switch# show vlan brief

    In leyoNET VLANs with a colour tint the ports on the canvas, the front panel and in the rack; an area with a VLAN documents the network.

    How to do it in leyoNET

    The same text as in the app’s help (F1 key).

    VLANs

    VLANs split one switch into separate networks. An access port belongs to exactly one VLAN, a trunk carries several (Trunks).

    Under Tools → VLANs each VLAN gets a name and a colour. The colour automatically tints every port of that VLAN on the canvas and in the port table. Between VLANs you need a router (Router on a stick) or a layer 3 switch.

    Creating VLANs: a switch only forwards VLANs it knows (tab Switching → VLANs on this switch or vlan 20, name Training). Assigning a new VLAN to an access port creates it, as on Cisco. A switch in the middle with trunks only still needs the VLANs, otherwise it drops the frames (console: «VLAN 20 is not created»). no vlan 20 deletes a VLAN, its ports become inactive. Files before version 1.2 have no list: there all VLANs in use count as created.

    Trunks

    A trunk links switches (or switch and router) and carries several VLANs on one cable. Each frame gets an 802.1Q tag with the VLAN number; the native VLAN runs untagged.

    Allowed VLANs: by default a trunk carries all created VLANs. With switchport trunk allowed vlan 10,20 only these; … add 30, … remove 10, … except 1, … all, … none. switchport trunk native vlan 99 changes the untagged VLAN (set it the same on both sides). show interfaces trunk shows allowed and active VLANs per trunk. In the form, native VLAN and allowed VLANs are in the port table.

    Router on a stick

    A router with a single cable to the switch routes between VLANs: the switch port is a trunk and the router has one subinterface per VLAN (e.g. eth0.10) with its own IP as gateway.
