    Running exams

    Exam file and key, variants per seat, exam mode, Safe Exam Browser, web version with seat codes and automatic evaluation.

    On this page
    1. Principle
    2. Creating an exam
    3. During the exam
    4. In the web version
    5. How to do it in leyoNET
    6. Read on

    Principle

    An exam consists of two files: the exam file for the learners (task, starting network, points per part, without check blocks and solutions) and the key for you (all check blocks, solutions, code to end the exam). Evaluation uses the key.

    Creating an exam

    • Generator: Tools → Create exam generates a company network with three sites, 84 points (21 per site, transit networks 9, network services 12), grade = 5 × points / 84 + 1. For the transit networks, the addresses count and whether the right routers are connected, not the port number. A separate variant per seat is possible.
    • Any task as an exam: Tools → Save as exam, with an empty starting network, devices only, the current network or as troubleshooting with random faults per seat.
    • With an AI (web version only, after signing in with the admin password): Tools → Tasks with AI creates instructions with rules, the schema of all checks and the open task as an example. You paste the AI's reply back; leyoNET checks it strictly and opens it in the task editor. Solve it once yourself, then save it as an exam. leyoNET sends nothing to an AI; do not give it personal data.
    • Fairer marking: partial points, follow-on errors (gateway “a router in its own network”), questions directly in leyoNET, “manual” blocks.

    During the exam

    Opening the exam file starts the exam mode: catalog, demos, task editor and opening other files are locked, a bar shows title, seat and time. It survives a reload and only ends with your code. For locked-down computers leyoNET generates a configuration for the Safe Exam Browser.

    In the web version

    In the admin console (/admin) → Exams → New exam, either create it here or upload the exam file and key. «Create here» offers two templates: troubleshooting (a finished company network with three sites and different faults at every seat; number and kinds selectable, the goals optionally do not reveal where the fault is) and build (M117) (each seat its own variant). In the web version only signed-in admins create exams. Then enter the exam time (required), print exam sheets (one page per seat with seat code, time, procedure and task) and hand them out, start. The cockpit shows the exit code on click; the server checks it with allowed attempts and a lock (adjustable, release locked seats in the cockpit). For the Safe Exam Browser, admin and quit password can also be entered as a SHA-256 hash, and further SEB settings can be chosen, e.g. a «Quit Safe Exam Browser» button after submitting. Work is saved every 20 seconds. With “📤 Submit” in the exam bar learners submit themselves: the seat is closed at once, the cockpit shows “submitted 10:42”, and learners get an empty canvas without a link to the submission. When time is up leyoNET submits automatically. Submitted by mistake: “Reopen” in the cockpit frees the seat with the remaining regular time, and the device reloads the work by itself. While an exam is running, the admin console shows a red bar at the top with “working · submitted · seats” and the time left. The exam cockpit shows per seat whether it is connected, allows extra time (+5′, +15′) and live “watching”. At the end leyoNET evaluates all seats, with manual correction and a report.

    Procedure, limits and what leyoNET can do against copying: exams (in German).

    How to do it in leyoNET

    The same text as in the app’s help (F1 key).

    Exams in the web version

    In the web version, exams run through the server without sending files back and forth.

    Teacher (admin console at /admin → Exams): - create here (admins only): template troubleshooting (finished company network with different faults at every seat, number and kinds selectable, optionally without hints in the goals) or build (M117) (each seat its own variant). Or upload the exam file and key. Set seats and the exam time (required) - code to end: the server checks it with allowed attempts and a lock (adjustable); release locked seats in the cockpit - print exam sheets or seat cards and hand them out: each seat has its own seat code. Who sits where is only in your seating list or on the sheet – the server knows no names - start, give extra time per seat (+5′, +15′, also later), end for everyone. While the exam is running, the admin console shows a red bar at the top with progress and time left - each seat shows “submitted 10:42” as soon as the person has submitted - evaluate automatically: all submissions corrected with the key; a name list (“07 Anna Example”) can be pasted into the review window and stays there only - download submissions: one file with all submissions and the key, which “Review submissions” can evaluate later

    Learners: File → Join exam … → seat code. Before the start they wait. Work is saved every 20 seconds. “📤 Submit” in the exam bar submits after a confirmation: the seat is then closed and an empty canvas begins. When time is up, it is submitted automatically. The server deletes everything after 60 days. Safe Exam Browser: When creating, choose «Safe Exam Browser only». The cockpit creates a SEB file with start, admin and quit password and a random exam key that is valid until the exam ends. Without SEB the server accepts neither joining nor saving. Admin and quit password can also be entered as a ready SHA-256 hash. Under «More SEB settings»: quitting allowed, a «Quit Safe Exam Browser» button after submitting, block quit shortcuts, reload, taskbar, clock, zoom, spell check, clipboard, virtual machine, screen sharing, Wi-Fi, microphone, camera, number of displays and further allowed addresses. SEB has no limit for password attempts; leyoNET limits the attempts for the code to end instead.

    Admin console

    The admin console of the web version is a page of its own: /admin (e.g. app.leyonet.ch/admin). “Admin” or Alt+A opens it in its own tab that can stay open next to the lesson.

    • Overview: running exams, classes, active sessions, security, feedback and check report; updated every 15 seconds. While an exam is running, a red bar at the top shows “working · submitted · seats” and the time left
    • Exams, classes and access as before; anything that needs the editor (watch, open, infrastructure) switches to the editor in the same tab and back with “Back to the admin console”
    • Sessions and statistics: key figures and all active sessions; watch, open, extend or delete each one. Technical data only, no content
    • Security: two-factor sign-in with an authenticator app (scan the QR code, confirm a code, keep the recovery codes), previous sign-in, end other sign-ins. The main admin can require two-factor for everyone

    The sign-in is valid only in this tab and ends after 60 minutes without activity. Privacy: no accounts, no cookies, no phone numbers or e-mail addresses; the authenticator app computes only on the phone.

    Tasks with AI

    Only in the web version after signing in with the admin password (Tools → Admin; learners do not see the tool): under Tools → Tasks with AI, leyoNET creates instructions (a prompt) for an AI of your choice: rules (private addresses only per RFC 1918/5737, domains ending in .example), the complete schema with all checks and the open task with its start network as an example. You can add what you want, e.g. “exam for M117, two VLANs with DHCP, 30 points”.

    • Copy instructions or Save as file and paste them into the AI.
    • Paste the AI's reply (a JSON object in the format “leyonet-ki-aufgabe”) here or open it as a file and click Import.
    • leyoNET checks everything strictly: device types, names, addresses, cables and every check. On an error nothing is imported and the message names the place.
    • The task is then in the editor. Solve it once yourself and save it as a task or with Tasks “Save as exam”.

    leyoNET does not connect to any AI and sends nothing. Do not give the AI personal data (names of learners).
