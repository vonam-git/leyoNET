    Wozu

    Menschen merken sich www.schule.example, Geräte brauchen 192.168.0.3. Das Domain Name System übersetzt Namen in Adressen. Jeder Rechner hat dafür einen DNS-Server eingetragen (fest oder per DHCP) und fragt ihn, bevor er eine Verbindung aufbaut.

    Einträge

    Typordnet zuBeispiel
    AName → IPv4-Adresseweb.schule.example A 192.168.0.3
    AAAAName → IPv6-Adresseweb AAAA 2001:db8::3
    CNAMEAlias → anderer Namewww CNAME web
    MXDomain → Mailserver (mit Vorrang)schule.example MX 10 mail
    NSDomain → zuständiger Nameserver
    PTRAdresse → Name (Rückwärtsauflösung)
    TXTfreier Text

    Jeder Eintrag hat eine TTL: So lange darf ein Client die Antwort im Cache behalten.

    Ablauf einer Abfrage

    1. Der Browser will www.schule.example und fragt den DNS-Server (UDP, Port 53).
    2. Der Server findet www als CNAME auf web und dazu den A-Eintrag.
    3. Er antwortet autorisierend mit der Kette; der Client merkt sich das Ergebnis.
    4. Kennt der Server die Zone nicht, leitet er weiter an einen anderen DNS-Server (z.B. den des Providers) und antwortet «nicht autorisierend».

    Beispielnamen enden auf .example, einer Domain, die nach RFC 2606 nie vergeben wird.

    In leyoNET

    Ein Server wird unter Erweitert → Dienste zum DNS-Server und bekommt eine Zone.

    C:\> nslookup www.schule.example
C:\> nslookup -type=MX schule.example
C:\> nslookup 192.168.0.3
C:\> ipconfig /displaydns
C:\> ipconfig /flushdns

    DNS

    DNS übersetzt Namen in Adressen und umgekehrt. Der Client fragt seinen DNS-Server per UDP Port 53 und merkt sich die Antwort für die Dauer der TTL (ipconfig /displaydns, ipconfig /flushdns).

    • A und AAAA: Name → IPv4- bzw. IPv6-Adresse
    • CNAME: Alias auf einen anderen Namen (der Server folgt der Kette)
    • MX: Mailserver einer Domain, der kleinste Vorrang gewinnt
    • TXT: Text, z.B. eine SPF-Regel
    • NS: Nameserver der Domain
    • PTR: Adresse → Name (Rückwärtsauflösung unter in-addr.arpa bzw. ip6.arpa)

    Namen aus der eigenen Zone beantwortet der Server autorisierend. Mit einer Weiterleitung fragt er für alle anderen Namen einen weiteren Server (z.B. den des Providers) und antwortet «nicht autorisierend». Testen mit nslookup -type=MX schule.example, nslookup 192.168.0.3 (PTR) oder nslookup name server (bestimmten Server fragen).

    Beispiel ansehen

    • DNS mit Weiterleitung

      Schul-DNS mit Zone schule.example (A, CNAME, MX, TXT, NS, PTR), der unbekannte Namen an den DNS des Providers weiterleitet.

      PC 1 löst einen Alias über zwei CNAME auf, fragt den Mailserver (MX) ab und öffnet eine Seite beim Provider: Der Schul-DNS leitet die Frage weiter und antwortet «nicht autorisierend».
